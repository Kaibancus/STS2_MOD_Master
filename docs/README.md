# 工程文档总览

本目录既描述目标，也明确哪些事项仍未实现。不要把计划中的内容当作已完成能力。

| 文档 | 负责的问题 | 不负责的问题 |
| --- | --- | --- |
| [PRD](prd.md) | 为什么做、做什么、不做什么、如何验收 | 代写角色创意或未经测量的工期 |
| [技术评估](technical-assessment.md) | 工具/版本、接口证据、方案比较、风险和待验证项 | 宣称尚未运行的探针成功 |
| [资料来源](references.md) | 官方/社区来源、版本和本地证据定位 | 上传游戏源码或私人分析输出 |
| [实施计划](implementation-plan.md) | 阶段、依赖、决策门、实施与发布边界 | 代替当前任务状态 |
| [工程管理入口](engineering/README.md) | 日志、任务、BUG/FIX 的统一入口 | 另建一套重复状态 |
| [本地开发边界](local-development.md) | 目录、工具隔离、玩家数据与公开边界 | 未证实的启动命令或自动恢复存档 |
| [角色设计](character-design.md) | 用户填写的角色设定与内容规则 | 工程代理自行补写模板、数值或内容配额 |

建议先阅读 PRD 与技术评估，再查看实施计划；开始实施前查任务和缺陷看板，
完成批次后更新日志。角色设计文件初始必须为空，工程文档对设计的未知项
采用明确的依赖门管理，而不是填入猜测。

初期没有构建项目，文档的一致性检查不需要安装额外编译、格式化或测试框架。
