# 工具、环境、接口与工程难点评估

状态：已批准的技术评估基线；已补充本版本离线存储的静态与受控运行证据，
角色/MOD 装载及资源兼容探针尚未执行。
来源 ID 对应 [资料来源](references.md)，功能范围见 [PRD](prd.md)。

## 1. 核心结论

1. 本项目是 C# / Godot 的 STS2 MOD，不是 STS1 的 Java / ModTheSpire / BaseMod 工程。
2. 当前版本已有原生入口、模型/池扩展、Hook 订阅、依赖排序和本地化装载。
   用户已选择原生接口优先，按探针证据引入最小必要依赖，不自动安装框架。
3. 角色表现接入并非所有成员都可重写。资源、场景、动画及角色 UI 仍是实质性难点，
   不能把“模型注册成功”等同于“完整角色可用”。
4. 本机 SDK9 已有基础能力。编辑器选型不能只看 GodotSharp 的 `4.5.1`：
   官方推荐的社区资料目前优先 MegaDot，需要区分 stock 和定制引擎。
5. 官方 MegaDot `4.5.1-m.14` C# Windows x64 便携候选包已下载、校验并完成版本查询，
   作为后续兼容探针候选；没有声明它已与本地完整资源流程兼容。
6. 玩家数据隔离是首次运行前的阻断门。普通/MOD 分区、备用档位、备份、
   游戏副本或编辑器便携模式均不能单独通过该门。
7. 当前增加独立离线存档入口；不替用户设计角色，不开始正式机制/卡牌实现。

## 5. 本地接口到工程职责的映射

| 能力 | 本版本证据 | 对实现的约束 |
| --- | --- | --- |
| 入口/装载 | `ModInitializerAttribute`、`ModManager.Initialize` | 自定义入口与无入口的自动 Harmony 路径不能混淆；模型/本地化初始化前完成必要注册 |
| 目录/依赖 | 原生递归 DLL/PCK 发现、依赖拓扑排序、用户排序 | DLL/PCK/Manifest 同一 MOD ID；不假定可热卸载；避免开发版与 Workshop 同 ID 竞争 |
| Manifest | PE 注解确认 `id/name/author/description/version/has_pck/has_dll/dependencies/affects_gameplay/min_game_version` | 依赖元素为含 `id/min_version` 的对象；类型存在不等于所有可选性/默认值已确认 |
| 模型/ID | `ModelDb`、`Inject(Type)`、`AllAbstractModelSubtypes`、`InitIds` | 注册、ID 初始化和预载有顺序；稳定 ID 不应随显示文案或普通重构变化 |
| 内容池 | `ModHelper.AddModelToPool`、`CardPoolModel.GetUnlockedCards` | 迟于池合并会报错；全量数据库不是合法奖励池；还要测试解锁/商店/图鉴 |
| 实例 | `AssertCanonical`、`AssertMutable`、`AfterCloned` | 在正确创建边界取得实例；注意浅拷贝订阅和跨玩家/跨局状态 |
| 角色 | `CharacterModel` 的属性、资源入口和动画方法 | 不只是初始血量/卡牌；选择/地图/休息点/商店/事件等资源入口也需矩阵 |
| 玩法 | `CardModel.OnPlay` 和 `CreatureCmd/CardPileCmd/PowerCmd/PlayerCmd` | 正确等待动作、上下文和生命周期，不直接改字段绕过钩子 |
| 表现 | `OnEnqueuePlayVfx`、角色视觉接口 | 入队表现回调不能放玩法逻辑；核心机制状态不存 UI 节点 |
| 本地化 | `LocString`、`DynamicVar`、`DynamicVarSet` | 实际结果、文本、升级与目标预览一致；确定发布语言后覆盖 |
| 随机 | `RunRngSet` 的分流 | 战斗生成不影响奖励流；视觉随机与玩法随机分离 |
| 保存 | `SavedProperties`、`SavedPropertyAttribute`、`SerializableCard` | 明确支持类型、顺序、恢复边界和字段/模型改名策略，不序列化整个对象图 |
| 数据路径 | `UserDataPathProvider`、本地/云 `ISaveStore` | normal/modded 分区不是测试隔离；共享设置、云端和首次迁移都要检查 |

静态元数据证明成员存在和可见性，不证明相关控制流和运行结果。

### S-01/S-02：本版本离线存储结论

补充证据 L07/L08 与 S23/S24：实际托管分支支持 `--force-steam=off`，
且只在 Steam 已初始化时构造云存储后端。仅在 Steam 客户端关闭 Cloud 选项
仍可能写本机 Steam 缓存，因此不能代替这个内置无 Steam 分支。

本版本原生 EXE 的 Windows 路径 getter 确实读取进程 `APPDATA`，
发行配置的自定义目录为 `SlayTheSpire2`。离线默认 local ID 为 `1`；
单独使用 `--clientId` 或 `--nomods` 不改变整个 `user://` 根。
固定 `--force-steam=off` 必须置于 `--` / `++` 分隔符之前；
不接受任意附加参数，因为解析器允许后出现的同名参数覆盖前值。

原生入口在创建进程前设置子进程 APPDATA/LOCALAPPDATA/TEMP/TMP；
保存、早期迁移和日志进入独立版本/slot 根。全发行文件指纹阻止未知版本、
额外 MOD 和 `override.cfg` 改写这个契约。普通设置与 mod_settings 账号级共用，
profile/进度/当前局/历史按 normal 或 modded 分区；离线后端不会触及 Steam 云缓存。
这个结论限于已核对的可信版本，不是对任意原生扩展或恶意 MOD 的 OS 级约束。

两次 guest 及一次获准宿主无界面实验实际到达主菜单并写入独立存档，
不是仅版本查询；guest 重启复用了同一组数据。日常入口不需要 Sandbox。
具体源数据复核、宿主验收和限制见工程日志；`Invalid Task ID` 无界面错误
保留为运行观察，不把有限的存储实验夸大为完整玩法或图形兼容验收。

### 角色接入的特别难点

直接继承 `CharacterModel` 需满足抽象的身份/颜色、初始属性、
CardPool/RelicPool/PotionPool、初始牌组/遗物、动画时机等契约。
存在 PotionPool 不代表产品必须制作新药水。

本版本 `CreateVisuals` 为公开非 virtual，`VisualsPath` 为 private；
某些图标路径、附加资源和动画入口可重写，其他资源 getter 不可。
BaseLib 的 `CreateCustomVisuals` / `CustomVisualPath` 是框架适配能力，
不得在文档或实现中当作原生虚方法使用。

场景编辑器不一定能直接使用游戏程序集里的脚本类；
普通图片/场景到游戏视觉节点的转换需要验证。
非 Spine 动画和 Godot 音频存在社区适配路径，因此商业制作工具不是默认前置。

## 6. 候选框架与模板评估

| 路线 | 合理价值 | 主要负担 | 决策 |
| --- | --- | --- | --- |
| 原生接口 + 自有窄适配 | 最小依赖、明确控制、利用当前已有扩展点 | 资源非虚入口等缺口需自己维护 | 当前首先验证 |
| 原生 + BaseLib 3.4.5 | 自定义角色/资源/UI/保存等能力，较完整作者文档 | 自身仍有 Harmony、async transpiler 与保存补丁，随版本漂移 | 只针对已证明缺口对比 |
| 原生 + RitsuLib 0.5.18 | 明确包含 0.111.0 目标，提供注册/RNG/保存等体系 | 体积/能力范围、回退和网络相关默认行为需审查 | 有具体需求时对比 |
| 多框架叠加 | 特定跨库生态可能需要 | 双重登记、同目标 patch、顺序和故障面增加 | 首期不默认使用 |

BaseLib 3.4.5 的工程目标是 net9/Godot SDK4.5.1，但源码要求 `LangVersion=14`。
消费已编译包与使用 SDK9 重编其源码不是同一个问题；
不能一面承诺不升级编译器，一面默认本地重编所有第三方源码。

ModTemplate 2.5.2 是参考，不可原样执行：已核对存在浮动版本、
build 后自动复制、publish 导出及 `WarnAndContinue`。
本项目应固定版本、分离 Build/Pack/Deploy，必要步骤失败必须阻断。
示例角色设定、数值和素材不属于已批准的产品输入。

RitsuLib 的 debug compatibility fallback 不能成为发布验收的成功依据，
网络/遥测相关能力也不能因引入框架就默认启用。
候选许可信息与源码版本见 S14-S18；正式采用时仍需核对具体包和资产。

## 8. 构建、部署、诊断和验证策略

未来管线分为 Compile → Validate → Pack → Deploy → Run；
每步独立、可失败、可定位，不让普通 build 自动写游戏目录或启动游戏。

游戏引用采用外部路径并审查 `Private=false` / CopyLocal，
但 `PrivateAssets=All` 和忽略规则都不能代替分发包检查。
白名单包只含自身 Manifest、DLL、PCK 及获准附属内容；
游戏依赖、工具包、真实数据和本机日志均排除。

本地调试使用匹配自身 DLL 的 PDB 和游戏日志，
启用控制台/启动参数前核对本版实现。日志先本地审查再最小化脱敏分享，
不安装远程日志服务，不默认网络上报。

公共 CI 可验证自身纯逻辑、文档、清单和授权元数据，
不能以把游戏 DLL 放进公共 artifact/NuGet 的方式实现集成测试。
真实游戏级回归使用拥有合法安装且经批准隔离的本地环境；
自托管和外部 PR 的权限问题另行评估，不在此阶段配置。

验证层次：静态基线 → 装载/接口探针 → 机制单元边界 →
可玩垂直切片 → 内容交互 → 存档/失败场景 → 原版非回归 →
干净本地安装。详细任务与退出门见实施计划。

## 9. 后置但需要保留的约束

联机本期不实现，但保留稳定 ID、确定性、正确选择上下文、
明确玩法影响标记及可序列化状态，避免制造将来必须全面重写的假设。
这不等于已承诺未来无需改造即可联机。

Workshop 本期不发布；以后应区分游戏 MOD Manifest 与上传工具配置，
审查包内容、版本和双副本加载关系，不能把官方 uploader 当成游戏加载器。

角色设计文件初始保持零字节。上述评估只规定工程契约和待验证问题，
不设定角色主题、机制、卡牌数量、数值、美术或商业工具采购。
