# BUG / FIX 看板

当前尚未登记已确认的本项目运行缺陷。游戏版本变化、资料滞后、
未知资源适配和未证明的存档隔离属于技术风险，不伪装成已经复现的 BUG。

状态流：待确认 → 已确认 → 修复中 → 待复验 → 已关闭；
复验不通过或问题再次发生时进入重新打开。

严重度：阻断 / 高 / 中 / 低。严重度衡量影响，不代表复现置信度或修复顺序的全部依据。
任何真实数据损坏风险都先停止相关操作，保留现场，不继续在真实档位上复现。

## 建单要求

每个问题给出可重复步骤、触发条件、实际与预期、发生频率或已知范围，
并注明游戏/MOD/依赖版本及是否在干净隔离环境复现。
提供日志时先移除账户 ID、本机路径、存档内容、令牌和其他私人数据。

初始仅为怀疑时标记“待确认”，不能在根因栏将猜测写成事实。
通用研究风险保存在技术评估的风险清单中，不为填满表格制造示例缺陷。

## 修复与关闭

- 修复任务关联工程任务和需求；记录必要的回归范围，不只记录代码改了哪里。
- “有修复提交”不等于“已关闭”；先进入待复验。
- 复验使用原复现步骤以及与根因相关的回归用例，记录实际版本和结果。
- 尚未执行时明确标记未执行；无法复现与已修复是不同结论。
- 重新打开时保留此前修复与复验历史，不覆盖成从未发生。
- 关闭后在工程日志追加结论；当前表保留缺陷记录，不删除以制造零缺陷统计。
